BAB IPendahuluan

1.1 Latar Belakang

Uji Kompetensi mahasiswa Program Pendidikan Vokasi Gizi (Diploma III Gizi dan Sarjana Terapan Gizi) dengan metode Objective Structured Clinical Examination (OSCE) menilai kemampuan peserta sampai tahap show how. Peserta berpindah dari satu station ke station berikutnya, dan pada setiap station penguji menilai kinerja peserta menggunakan rubrik terstandar, lalu memberikan penilaian kesan umum (global performance).

Penilaian secara manual di atas kertas membutuhkan waktu rekapitulasi yang panjang, rentan salah hitung, dan menyulitkan penghitungan Nilai Batas Lulus dengan Borderline Regression Method sebagaimana diamanatkan pedoman. Karena itu Bidang IT AIPVOGI mengembangkan Aplikasi Penguji OSCE Vokasi Gizi: aplikasi web progresif (PWA) yang dipakai penguji untuk menginput nilai langsung di station, menyimpan data ke Google Sheets, dan menghasilkan rekap kelulusan dalam format Excel.

1.2 Tujuan Buku Manual

  • Menjadi panduan pemasangan dan konfigurasi aplikasi bagi admin/pengelola TI institusi.
  • Menjadi panduan pengelolaan data ujian (periode, peserta, penguji, rubrik) di Google Sheets.
  • Menjadi panduan penggunaan aplikasi bagi penguji dan admin pada hari pelaksanaan ujian.
  • Menjelaskan cara aplikasi menghitung nilai, batas lulus, dan status kelulusan peserta.

1.3 Acuan

Aplikasi dan buku manual ini mengacu pada Pedoman Penyelenggaraan Uji Kompetensi dengan Metode OSCE Vokasi Gizi yang disusun bersama oleh DPP PERSAGI, Kolegium Ilmu Gizi Indonesia (KIGI), dan AIPVOGI, beserta Surat Edaran Bersama tanggal 7 Agustus 2023 tentang himbauan penyelenggaraan Uji Kompetensi metode OSCE secara mandiri institusional.

BAB IIGambaran Umum Aplikasi

2.1 Fitur Utama

  • Input nilai di station: penguji hanya melihat station dan rubriknya sendiri; skor × bobot dan total dihitung otomatis.
  • Layar periksa kembali sebelum disimpan; setelah disimpan nilai dikunci dan hanya dapat dikoreksi admin.
  • Bisa offline: nilai disimpan di perangkat dan terkirim otomatis begitu ada internet, tanpa nilai ganda.
  • Pengaman data berlapis: penyimpanan permanen, larangan keluar selama ada nilai belum terkirim, dan file cadangan.
  • Rekap otomatis: progres per station, matriks peserta, Nilai Batas Lulus (Borderline Regression), dan status kelulusan.
  • Unduh Excel: rekap lengkap untuk arsip, yudisium, dan bukti akreditasi.
  • Rubrik fleksibel: rubrik dan kasus dapat diganti per periode, termasuk impor otomatis dari file template soal (.docx) tanpa mengetik ulang.
  • Waktu setempat: waktu penilaian otomatis tercatat dalam WIB, WITA, atau WIT sesuai lokasi perangkat.

BAB IIIInstalasi dan Konfigurasi

Bab ini ditujukan bagi admin atau pengelola TI. Instalasi cukup dilakukan satu kali. Seluruh langkah menggunakan akun Google dan akun GitHub resmi AIPVOGI.

3.1 Menyiapkan Google Sheets

  1. Login Google dengan akun aipvogi.official@gmail.com, lalu buat Google Sheet baru, misalnya bernama Database Penguji OSCE.
  2. Buka menu Ekstensi → Apps Script. Hapus isi file Code.gs, lalu tempel seluruh isi file apps-script/Code.gs dari paket aplikasi. Klik ikon simpan.
  3. Buka ⚙ Setelan Project, ubah Zona waktu menjadi zona kantor pusat (misalnya GMT+07:00 Jakarta atau GMT+08:00 Makassar).
  4. Kembali ke editor, pilih fungsi setup pada dropdown, lalu klik ▶ Jalankan. Pada permintaan izin pilih Tinjau izin → pilih akun → Lanjutan → Buka proyek → Izinkan.
  5. Setelah eksekusi selesai, Sheet otomatis berisi tab PERIODE, PAKET, STATION, RUBRIK, PESERTA, PENGUJI, NILAI, LOG lengkap dengan rubrik standar, serta satu akun admin dengan PIN 909090.
Penting

Segera ganti PIN admin 909090 di tab PENGUJI dengan angka lain yang hanya diketahui admin.

3.2 Memasang Web App (API)

  1. Di editor Apps Script klik Terapkan → Deployment baru, pilih jenis Aplikasi web.
  2. Isi Jalankan sebagai: Saya; Yang memiliki akses: Siapa saja. Klik Terapkan.
  3. Salin URL Web App yang berakhiran /exec.
  4. Buka URL tersebut di browser. Bila muncul teks {"ok":true,"app":"Penguji OSCE Vokasi Gizi",...}, API sudah aktif.
Bila Code.gs diperbarui

Gunakan Terapkan → Kelola deployment → Edit (ikon pensil) → Versi: Versi baru → Terapkan. Dengan cara ini URL Web App tidak berubah.

Buka file js/config.js lalu isi API_URL dengan URL Web App. Pengaturan lain dalam file yang sama:

3.4 Mengunggah Aplikasi ke GitHub Pages

  1. Buka repositori github.com/aipvogiofficial/Penguji-OSCE, klik Add file → Upload files, unggah seluruh isi folder aplikasi (termasuk subfolder css, js, icons, vendor), lalu Commit changes.
  2. Buka Settings → Pages. Pada Source pilih Deploy from a branch, branch main, folder /(root), lalu Save.
  3. Setelah 1–2 menit aplikasi dapat dibuka di https://aipvogiofficial.github.io/Penguji-OSCE/.

3.5 Memperbarui Aplikasi

Bila file Code.gs berubah, tempel ulang isinya di editor Apps Script lalu terapkan sebagai versi baru (Subbab 3.2) agar URL tetap sama. Setiap kali berkas aplikasi diubah, naikkan nomor versi pada baris var VERSI = 'penguji-osce-v1.2.0' di file sw.js (misalnya menjadi v1.2.1). Perangkat penguji akan menampilkan pemberitahuan Versi baru aplikasi tersedia → Muat ulang.

Koreksi nilai

Bila nilai perlu dikoreksi (misalnya salah pilih skor), admin mengubah langsung kolom B1–B8 atau Global Rating pada baris yang bersangkutan dan menuliskan alasan pada kolom Keterangan. Rekap selalu dihitung ulang dari skor butir sehingga total tidak perlu diperbaiki manual.

4.6 Mengubah Rubrik

Rubrik disimpan di Google Sheets dalam bentuk paket, sehingga perubahan tidak memerlukan perubahan aplikasi. Paket otomatis ditandai Terkunci = YA begitu ada nilai yang masuk. Ada tiga cara menyiapkan rubrik baru:

a. Cara paling praktis: impor dari template soal (.docx)

Rubrik tidak perlu diketik ulang. Admin cukup mengunggah file soal yang disusun dosen sesuai template Lampiran III pedoman; aplikasi membaca nomor station dan tabel Rubrik Penilaian (kompetensi, kriteria skor 0–3, bobot). File dibaca di perangkat admin dan tidak diunggah ke mana pun; skenario klinik serta instruksi penguji dan pemeran standar tidak dibaca.

  1. Login sebagai admin, lalu pada panel Paket rubrik klik Impor Rubrik dari Template Soal (.docx).
  2. Pilih Program (D3 atau Sarjana Terapan), isi Kode paket baru (misalnya D3-2027-A) dan keterangan.
  3. Klik Pilih file soal dan pilih semua file soal sekaligus (satu file per station).
  4. Periksa pratinjau per station. Nomor station dibaca otomatis dari judul "Stasion – n", dari baris Nomor station (angka lain dicoret), atau dari nama file (misalnya St5_Stunting.docx); bila tidak terbaca, pilih manual.
  5. Lengkapi yang ditandai merah, misalnya bobot yang kosong. Baris alternatif berwarna kuning (mis. "atau hanya 1 pengukuran TB") otomatis tidak dipakai; centang bila ingin dipakai. Ubah nama kasus bila perlu.
  6. Station yang tidak diunggah filenya memakai rubrik paket standar (opsi dapat dimatikan).
  7. Klik Simpan sebagai paket. Tab PAKET, STATION, dan RUBRIK terisi otomatis. Terakhir, isi Kode Paket tersebut pada periode di tab PERIODE.
Agar terbaca dengan baik

Gunakan template soal sesuai pedoman tanpa mengubah susunan kolom tabel rubrik (NO, Kompetensi, Skor = 0, Skor = 1, Skor = 2, Skor = 3, Bobot). Satu file berisi satu station. Sub-butir bernomor 1.1, 1.2, dst. dibaca sebagai butir tersendiri dengan judul induknya.

b. Paket belum terkunci: edit langsung

  • Ubah teks Kompetensi atau Skor 0–3 serta angka Bobot langsung di tab RUBRIK.
  • Untuk menambah butir, sisipkan baris dengan Kode Paket dan No Station yang sama, lalu beri No Butir berikutnya (maksimal 8 butir per station). Untuk menghapus butir, hapus barisnya lalu rapikan kembali penomoran.
  • Gunakan Data → Buat filter untuk menyaring per paket dan per station.
  • Setelah diubah, penguji harus memilih menu Muat ulang data peserta & rubrik (atau keluar lalu login kembali), karena rubrik tersimpan di perangkat.

c. Paket sudah terkunci atau untuk periode baru: buat paket baru secara manual

  1. Tab PAKET: tambahkan baris, misalnya D3-2027 | D3 | Rubrik periode 2027 | TIDAK.
  2. Tab STATION: salin seluruh baris paket lama (8 baris D3 atau 9 baris Sarjana Terapan), tempel di bawahnya, ganti Kode Paket menjadi D3-2027, lalu sesuaikan judul/kasus.
  3. Tab RUBRIK: salin seluruh baris paket lama, ganti Kode Paket, lalu edit isi rubrik.
  4. Tab PERIODE: isi Kode Paket periode baru dengan D3-2027.
Jangan ubah paket yang terkunci

Rekap dihitung menggunakan bobot yang tercatat di Sheet. Mengubah bobot paket yang sudah dipakai akan mengubah hasil periode lama. Untuk perubahan apa pun pada paket terkunci, buatlah paket baru.

4.7 Data Contoh untuk Uji Coba

Muat ulang Google Sheet hingga menu OSCE muncul, lalu pilih OSCE → Isi data contoh. Sistem menambahkan periode UJICOBA-D3 dan UJICOBA-STR, masing-masing dengan 10 peserta contoh, serta PIN penguji contoh: D3 3101, 3102, 3103, 3105, 3106, 3107 dan Sarjana Terapan 4101, 4102, 4103, 4105, 4106, 4107, 4108 (angka terakhir = nomor station). Hapus atau ubah status periode uji coba menjadi SELESAI sebelum ujian sesungguhnya.

BAB VPanduan Penguji

5.1 Persiapan Perangkat

  • Perangkat: HP, tablet, atau laptop dengan browser terbaru (Chrome, Edge, atau Safari).
  • Jam dan zona waktu perangkat diatur otomatis.
  • Baterai terisi penuh; siapkan pengisi daya.
  • Jangan gunakan mode penyamaran/incognito.

5.2 Membuka dan Memasang Aplikasi

Buka alamat aipvogiofficial.github.io/Penguji-OSCE. Halaman cover menampilkan logo AIPVOGI dan tombol Masuk dengan PIN. Disarankan memasang aplikasi ke layar utama agar data penilaian lebih aman:

  • Android / laptop (Chrome, Edge): klik tombol Pasang aplikasi di perangkat ini pada cover, atau menu browser → Instal aplikasi.
  • iPhone / iPad (Safari): ketuk tombol Bagikan lalu pilih Tambahkan ke Layar Utama.

5.3 Login

  1. Login dilakukan saat ada internet, idealnya ketika briefing H-1 atau sebelum sesi dimulai.
  2. Ketuk Masuk dengan PIN, ketik PIN dari panitia, lalu ketuk Masuk.
  3. Aplikasi mengunduh daftar peserta dan rubrik station Anda ke perangkat. Setelah itu penilaian dapat dilakukan walaupun internet terputus.

5.4 Halaman Daftar Peserta

Bagian atas menampilkan nomor station, periode, nama penguji, status koneksi, serta jumlah peserta yang sudah dan belum dinilai. Peserta diurutkan sesuai nomor urut rotasi dan dapat dicari berdasarkan nama, NIM, atau nomor urut. Arti label status:

LabelArti

5.5 Menginput Nilai

  1. Ketuk nama peserta yang sedang berada di station.
  2. Untuk setiap butir kompetensi, ketuk skor 0, 1, 2, atau 3. Kriteria skor yang dipilih langsung tampil di bawah tombol. Ketuk Lihat semua kriteria untuk membandingkan seluruh kriteria.
  3. Label Bobot (kuning = 1, biru muda = 2, hijau = 3) menunjukkan tingkat kesulitan butir. Actual Mark di bagian bawah layar dihitung otomatis.
  4. Pilih Global Performance: Tidak Lulus, Borderline, Lulus, atau Superior, sesuai kesan umum Anda terhadap penampilan peserta.
  5. Isi catatan bila perlu, lalu ketuk Periksa & Simpan.
Draf otomatis

Isian yang belum disimpan tersimpan otomatis sebagai draf. Bila aplikasi tertutup atau Anda kembali ke daftar, isian tidak hilang.

5.6 Memeriksa dan Mengunci Nilai

Sesuai pedoman, penguji wajib meneliti kembali penilaian sebelum menilai peserta berikutnya. Layar Periksa kembali penilaian menampilkan skor, bobot, nilai per butir, Actual Mark, dan Global Performance. Centang pernyataan Saya sudah meneliti kembali penilaian ini, lalu ketuk Simpan & Kunci.

Setelah disimpan, nilai terkunci dan tidak dapat diubah dari perangkat penguji. Bila ternyata ada kesalahan, laporkan kepada admin untuk dikoreksi (Subbab 4.5).

5.7 Bekerja Tanpa Internet

Bila koneksi terputus, bilah status berubah menjadi Offline. Penilaian tetap dapat dilakukan seperti biasa; nilai disimpan di perangkat dengan label Belum terkirim dan bilah status menampilkan jumlah nilai yang belum terkirim. Begitu internet tersambung kembali, nilai terkirim otomatis. Anda juga dapat mengetuk Kirim sekarang.

5.9 Mengakhiri Sesi

  1. Pastikan bilah status menampilkan Semua nilai sudah terkirim.
  2. Pilih menu Unduh file cadangan nilai dan simpan file tersebut (atau serahkan kepada admin bila diminta).
  3. Isi dan tandatangani lembar penilaian manual sesuai ketentuan pedoman.
  4. Pilih menu Keluar bila perangkat akan dipakai penguji lain.

BAB VIPanduan Admin

6.1 Login Admin dan Memuat Data

  1. Pada halaman cover ketuk Masuk dengan PIN dan masukkan PIN admin.
  2. Pilih periode ujian pada daftar, lalu klik Muat data. Data terakhir yang dimuat tetap tersimpan sehingga dapat dilihat walaupun sedang offline.
  3. Klik Muat data kembali kapan saja untuk memperbarui progres.

6.2 Progres per Station

Menampilkan jumlah nilai yang sudah masuk pada setiap station beserta nama penguji yang bertugas. Bilah progres di bagian atas menunjukkan persentase seluruh nilai yang sudah masuk.

6.3 Matriks Peserta

Tabel peserta × station berisi Actual Mark dan Global Rating. Sel hijau berarti lulus station, merah berarti tidak lulus, dan tanda "–" berarti belum dinilai. Selama nilai belum lengkap, NBL dan status masih bersifat sementara.

6.4 Batas Lulus (NBL)

Menampilkan untuk setiap station: skor maksimal, jumlah peserta dinilai (n), koefisien regresi a dan b, R², NBL, serta metode yang digunakan. Penjelasan perhitungan terdapat pada BAB VII.

6.5 Hasil Kelulusan

Menampilkan jumlah peserta Lulus, Tidak Lulus, dan Belum Lengkap, serta daftar station yang tidak lulus untuk setiap peserta.

6.6 Mengunduh Excel Rekap

Klik Unduh Excel Rekap. File Rekap_OSCE_[kode periode]_[tanggal-jam].xlsx berisi:

6.7 Mengimpor File Cadangan

Bila perangkat penguji rusak, hilang, atau tidak sempat mengirim nilai, nilai dapat dipulihkan dari file cadangan (.json) milik penguji:

  1. Muat data periode yang bersangkutan, lalu klik Impor Cadangan.
  2. Pilih file cadangan; aplikasi menampilkan nama penguji, periode, station, dan jumlah nilai. Klik Impor.
  3. Hasil impor menampilkan jumlah nilai baru, nilai yang sudah ada (sama), konflik, dan yang ditolak. Nilai yang sudah ada di server tidak pernah ditimpa.

BAB VIIPenilaian dan Penetapan Kelulusan

7.1 Actual Mark

Setiap butir kompetensi diberi skor 0–3 dan dikalikan bobotnya. Actual Mark (AM) station adalah jumlah seluruh hasil kali tersebut.

AM = Σ (skor butir × bobot butir)    Skor maksimal = Σ (3 × bobot butir)

Contoh D3 station 1 (DM Tipe 2), butir berbobot 1, 3, 1, 2 dengan skor 2, 3, 1, 3: AM = 2×1 + 3×3 + 1×1 + 3×2 = 18 dari skor maksimal 21.

7.2 Global Rating

Penguji memberikan kesan umum terhadap penampilan peserta secara keseluruhan: 1 Tidak Lulus, 2 Borderline (batas bawah kelulusan), 3 Lulus, 4 Superior. Global rating diberikan secara independen dari penghitungan skor butir.

7.3 Borderline Regression Method

Untuk setiap station, aplikasi menghitung regresi linear dengan Global Rating sebagai variabel bebas dan Actual Mark sebagai variabel terikat, menggunakan data seluruh peserta pada periode tersebut:

AM = a + b · GR    →    NBL = a + 2b

NBL adalah nilai AM pada titik GR = 2 (borderline), yaitu kemampuan minimum seorang nutrisionis untuk station tersebut. Peserta lulus station bila AM ≥ NBL.

7.4 Batas Cadangan

Regresi tidak dapat diandalkan bila datanya terlalu sedikit atau tidak bervariasi. Pada kondisi berikut aplikasi memakai Batas Cadangan = persentase (kolom Batas Cadangan (%) di tab PERIODE, bawaan 60%) × skor maksimal station:

  • jumlah peserta yang dinilai di station kurang dari 10 (dapat diatur melalui MIN_PESERTA_BRM);
  • seluruh peserta mendapat Global Rating yang sama; atau
  • kemiringan regresi (b) bernilai nol atau negatif.

Metode yang dipakai untuk setiap station selalu dicantumkan pada tab NBL di aplikasi dan di Excel rekap.

BAB VIIIKeamanan Data dan Pemecahan Masalah

8.1 Lapisan Pengaman Data

  1. Penyimpanan perangkat: setiap nilai yang dikunci langsung tersimpan di basis data browser (IndexedDB), bukan cache biasa.
  2. Penyimpanan permanen: aplikasi meminta browser agar data tidak dibersihkan otomatis.
  3. Sinkronisasi berkala: nilai dikirim saat disimpan, saat internet kembali, saat aplikasi dibuka, dan setiap 30 detik.
  4. Tanpa nilai ganda: kombinasi periode + station + NIM bersifat unik; pengiriman ulang tidak menggandakan data.
  5. Keluar ditahan selama masih ada nilai yang belum terkirim.
  6. File cadangan yang dapat diimpor admin.
  7. Lembar penilaian manual sesuai pedoman sebagai cadangan terakhir.

8.2 Zona Waktu

Aplikasi dapat digunakan di seluruh wilayah Indonesia. Waktu penilaian tercatat sesuai jam perangkat penguji beserta zonanya: WIB (Sumatera, Jawa, Kalimantan Barat dan Tengah), WITA (Bali, Nusa Tenggara, Kalimantan Selatan, Timur, dan Utara, Sulawesi), atau WIT (Maluku dan Papua). Pastikan pengaturan tanggal dan waktu perangkat penguji dalam mode otomatis.
